Where Can a Robot End Up?

Reachability bounds for sliding-robot puzzles, from loose to exact

The Setup

Imagine a grid with several robots on it. When you move a robot, it doesn't step one square — it slides in the chosen direction until it slams into another robot, stopping in the cell right next to that blocker. Two rules constrain the movement:

  1. No voluntary stopping. A robot can't stop in the middle of an empty lane. It keeps going until something stops it.
  2. Another robot must stop it. If a robot would slide off the edge of the board without hitting another robot first, that move is illegal. You simply can't make it.

The question: Given a starting arrangement of robots, which cells could any robot ever land on, across all possible sequences of legal moves?

Square vs. hex boards

The puzzle comes in two flavors. On square boards, robots slide in 4 directions. On hex boards, robots get 2 additional diagonal directions, for 6 total:

We'll analyze each bound for both board types, noting where the hex diagonals create differences.

1 The Board Itself

Claim: No robot can leave the board. Obvious from the rules and true for both square and hex boards. This is the loosest possible bound.

2 The Bounding Box

Claim: No robot can ever leave the smallest axis-aligned rectangle that encloses all robots in the starting position.

Proof (by induction on the number of moves)

Base case: All robots start inside the bounding box by definition.

Inductive step: Assume every robot is inside the box. A legal move changes one robot; the rest stay put. We show the slider's new position is still inside the box.

Consider the rightmost boundary, cmax. For the slider to land beyond cmax, it would need a blocker at column cmax + 2 or further right. But by hypothesis, every robot is at column ≤ cmax. No such blocker exists. In fact, if the blocker is at column cb ≤ cmax, the slider lands at cb − 1 < cmax.

The identical argument holds for all four boundaries (left, right, top, bottom). □

Hex boards

The two diagonal directions (−1, +1) and (+1, −1) also preserve the bounding box. When a robot slides diagonally, its row and column change in opposite directions. The slider lands one step before the blocker, so:

  • Direction (−1, +1): The slider's new row = blocker's row + 1 > rmin. Its new column = blocker's col − 1 < cmax. Both within bounds.
  • Direction (+1, −1): Mirror image. New row < rmax, new column > cmin.

The bounding box is preserved for all 6 hex directions.

3 The Convex Hull

The bounding box is a rectangle — a blunt instrument. We showed it works by proving that min and max of row and column can't grow. But there's nothing special about "row" and "column." The same argument works for any direction of measurement.

The general result

Think of laying a ruler across the grid at some angle. Each robot has a position along that ruler. We claim the ruler's min and max readings can never grow, no matter how the robots move.

Formally: pick any linear measurement of position, like "2×row + 3×column," or "row − column," or any combination a × r + b × c. We call this a ruler.

Theorem: Every ruler's range is preserved.

When a robot slides in direction (dr, dc) and lands one step before a blocker, the ruler f = a · r + b · c changes by a · dr + b · dc at each step along the slide. There are three cases:

  • The ruler increases along the slide (a · dr + b · dc > 0): The slider's new f-value is one increment below the blocker's. Since the blocker is inside the hull (induction), its f ≤ max(f), so the slider's is strictly less. And since f increased from the start, the slider's new value ≥ its starting value ≥ min(f).
  • The ruler decreases along the slide (a · dr + b · dc < 0): Mirror of the above.
  • The ruler is constant along the slide (a · dr + b · dc = 0): The slider's value doesn't change. Trivially preserved.

In all three cases, the slider's new ruler value stays within [min(f), max(f)]. Since this holds for every ruler f, every robot stays inside the intersection of all halfplane constraints — which is exactly the convex hull of the initial positions. □

Why this matters: The bounding box is the special case using only two rulers (r and c), giving 4 halfplane constraints. By adding more rulers, we get tighter polygons:

  • 2 rulers (r, c): bounding box (rectangle, 4 sides)
  • 4 rulers (r, c, r+c, r−c): octagonal bound (up to 8 sides)
  • All possible rulers: the full convex hull — the tightest possible convex bound

In practice, for a handful of robots, the exact convex hull is trivial to compute — it's just the polygon through the outermost robot positions.

Hex boards

The convex hull theorem applies to all 6 hex directions with no changes — the proof only uses the one-step-before-blocker rule, not the specific direction vectors. The convex hull of the initial positions is preserved on hex boards too.

For hex boards, the intermediate polygon approximations have a natural interpretation using the three hex "axes":

  • 2 rulers (r, c): bounding box (4 sides)
  • 3 rulers (r, c, r+c): hexagonal bound (up to 6 sides) — uses the three axes aligned with the six hex movement directions
  • 4 rulers (r, c, r+c, r−c): octagonal bound (up to 8 sides) — adds the "bonus" ruler r−c, which is not aligned with any hex direction yet is still preserved
  • All rulers: the full convex hull

4 The Orthogonal Convex Hull

All the bounds so far are convex — they're polygons with no indentations. But the actual set of reachable cells can be wildly non-convex. The orthogonal convex hull breaks out of convexity to get a much tighter fit.

Definition

A region on the grid is orthogonally convex if it has no gaps along any row or column: for any row, the cells in the region on that row form a single contiguous run (or the row is empty). Same for every column.

The orthogonal convex hull (OCH) of the robot positions is the smallest orthogonally convex region containing all of them. Compute it by filling gaps: if two robots (or previously filled cells) are in the same row, fill all cells between them; same for columns; repeat until stable.

The OCH is guaranteed to be a subset of the convex hull, because any convex region is automatically orthogonally convex (a convex region intersected with a horizontal line is always a single segment). Since the OCH is the smallest orthogonally convex set, and the convex hull is an orthogonally convex set, we have OCH ⊆ convex hull.

Proof for square boards

Theorem: No robot can leave the OCH of the starting configuration.

Let H be the OCH of the initial positions — a fixed set computed once.

Base case: Every robot starts inside H by construction.

Inductive step: Assume every robot is inside H. A move changes one robot; the rest stay in H. We show the slider's new position is in H using two facts:

  1. Mechanical fact: The slider and blocker are on the same row (horizontal slide) or same column (vertical slide). The landing spot is between them.
  2. Geometric fact: H is orthogonally convex. Two cells of H on the same row have every cell between them also in H. Same for columns.

The slider starts in H and the blocker is in H (inductive hypothesis). They share a row or column. By orthogonal convexity, every cell between them on that shared line is in H. The landing spot is between them, so it's in H. □

Hex boards: the standard OCH breaks

On hex boards, diagonal slides break the square OCH proof. The slider and blocker share a rising diagonal (r + c = constant), not a row or column. The standard OCH guarantees no gaps along rows and columns, but says nothing about diagonals.

The fix: Define a region as hex-orthogonally convex if it has no gaps along any row, any column, or any rising diagonal (r+c = constant). The hex-OCH is the smallest such region containing all robots.

The proof is then identical: for any hex move, the slider and blocker share a row, a column, or a rising diagonal. The hex-OCH is connected along all three, so the landing spot is inside.

In the example above, the hex-OCH fills (1, 1) to connect A and B along their shared diagonal r+c=2.

The OCH Is Not Exact

The orthogonal convex hull is a much tighter bound than the convex hull, but it still overestimates the true reachable set.

Counterexample: two robots on a line

Robots A and B at columns 0 and 5. The OCH fills the entire row between them. But:

  • A slides right, stopped by B → A lands at column 4. Now adjacent at 4 and 5.
  • B slides left, stopped by A → B lands at column 1. Now adjacent at 0 and 1.

From either adjacent position, neither robot can reach the interior. Actual reachable set: {0, 1, 4, 5} — four of six cells. The OCH doesn't see the "adjacency trap" that prevents interior access.

5 Exhaustive Search

The only way to find the exact reachable set is brute-force search:

  1. Start with the initial arrangement.
  2. Try every legal move, generating new arrangements.
  3. For each new arrangement, repeat step 2.
  4. When no new arrangements appear, stop.
  5. Collect every cell occupied by any robot in any visited arrangement.

This breadth-first search is guaranteed to find the exact set. The cost: with k robots on an N × N board, the state space can reach N2k configurations. Feasible for small puzzles, expensive for large ones. The same approach works identically for square and hex boards.

All Bounds Compared

Each bound is strictly tighter than the one above it (in general):

  • The bounding box is smaller than the board whenever robots don't fill the grid.
  • The convex hull is smaller than the bounding box whenever robots aren't arranged in a rectangle.
  • The OCH is smaller than the convex hull whenever robots aren't arranged in a convex blob — its staircase boundary follows the actual robot geometry far more closely.
  • The exact reachable set is smaller than the OCH because the OCH ignores how robots physically interact — it only knows about alignment, not adjacency.

The first four bounds are cheap to compute from the starting positions. The fifth requires exploring the full game tree. The conceptual divide is between convex bounds (bounds 2–3, which are polygons getting closer to the convex hull) and connectedness bounds (bound 4, which breaks out of convexity entirely). Each world has a natural "tightest" answer: the convex hull is the tightest convex bound, and the OCH is the tightest connectedness bound.
